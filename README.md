# 饥荒：联机版 AI 玩家

**简体中文** | [English](README.en.md)

这是一个由服务器控制的 AI 玩家模组，支持同时启用 0–5 个机器人。在新世界或已启用模组的旧存档中，真人进入后，机器人会先以 **[AI]** 条目出现在游戏内玩家列表，自行通过模型选择角色，再进入世界执行基础自主生存动作。每个 AI 都有独立的 API 地址、API Key 和模型名称，可以混用不同服务商，也可以重复使用同一个 Key。

这些是模组控制的机器人，玩家列表由模组扩展。它们不是独立的 Steam/WeGame 网络客户端，不占用经过身份认证的客户端席位，也不会作为连接出现在外部服务器浏览器中。

## 游戏内配置

1. 安装主模组。若需要在尚未启用服务器模组时，通过“已安装模组”菜单编辑配置，请将 `client_config_helper` 的内容复制到独立的同级目录 `mods/ai_players_config`，启用客户端模组 **AI Players Config**，然后重启一次游戏。配置助手必须是独立模组，不能只是主模组里的子目录。本地开发安装也可在游戏的 `mods/modsettings.lua` 中加入 `ForceEnableMod("ai_players_config")`；删除这一行即可取消自动加载。
2. 打开 **AI Players** 配置，将 **AI player count** 设为 0–5。界面会显示相同数量的配置组，每组包含 **AI N API URL**、**AI N API key**、**AI N Model** 和 **AI N API format**；数量为 0 时不显示服务商字段。
3. 分别填写每个 AI 的地址、Key 和模型。例如，AI 1 可以使用中转服务的地址、Key 和模型，AI 2 使用 `https://api.openai.com/v1`、自己的 OpenAI Key 和 `gpt-4o-mini`。接口须兼容所选的 OpenAI Chat Completions 或 Responses 协议。只有 Key 会遮挡显示，地址和模型保持可见。减少 AI 数量只会隐藏多余配置组，不会清除已填内容。
4. 地址或模型留空时，升级存档优先使用旧版共享配置；全新配置默认使用 `https://api.openai.com/v1` 和 `gpt-4o-mini`。每个 AI 显式填写的值始终优先，且不会成为其他 AI 的默认值。旧版共享地址、模型字段已隐藏。
5. 点击 **Apply**，通过游戏原生的主机配置机制保存。重新打开后会保留字段及组数；**Back** 放弃未保存的修改；**Reset** 恢复默认值，包括 AI 数量为 0、隐藏所有服务商字段。
6. 在运行世界服务器的电脑上启动 API 桥接程序。Windows 可双击 `tools/start_ai_bridge.cmd` 并保持窗口打开；需要 Python 3，无需额外依赖。也可运行 `python tools/ai_http_bridge.py`，Linux 使用 `python3`。桥接仅监听 `http://127.0.0.1:17893`，访问 `http://127.0.0.1:17893/health` 应返回 `{"ok":true}`。远程专用服务器必须在服务器本机启动桥接。
7. 在世界的“服务器模组”中启用 **AI Players**，创建或继续世界，然后用真人角色进入。打开游戏内玩家列表，各机器人先显示 **Selecting**，选角并在真人附近进入后显示所选角色和 **Alive**，死亡后显示 **Dead**。机器人默认独立处理食物、材料和照明需求，而不是跟随。仅启用配置助手不会启动机器人。旧存档只需在继续游戏前启用服务器模组，无需重新建档。

配置助手负责在前端初始化输入界面：未启用的服务器模组不会因为打开配置页而自动执行自己的前端入口。助手还会使用主机配置打开 AI Players 设置，避免在“已安装模组”中修改的内容被保存到独立的客户端配置。其他模组行为保持不变。世界仍须启用主模组才能生成机器人；专用服务器可直接使用下方配置示例，无需安装客户端助手。

## 自主取名与模组角色

进入世界前，每个 AI 会在原有选角请求中同时决定自己的名字和角色，不额外增加取名请求。玩家列表随后显示 `[AI] 自选名字`，后续模型观察也包含该名字。支持中文等 UTF-8 名称；控制字符会被移除，首尾空白会被清理，最多保留 48 个字符。名字无效或缺失时使用 `AI N`，不影响合法角色的选择。

候选角色读取当前世界的原版角色表与 `AddModCharacter` 注册表，并检查实际预制体是否已加载；不再限定旧版的 9 个角色。被其他模组移除的原版角色、仅用于变身的内部角色，以及未加载的角色不会提供给模型。**仅安装角色模组不够，必须在该世界启用，并按角色模组要求让所有客户端加载。** 不会自动下载或启用其他模组。

选角无效或超时会回退到可用角色；模组角色生成失败会尝试可用的安全默认角色，没有可用角色时不生成。名字与角色在每次世界会话重新选择，不跨会话持久保存。通用生存逻辑不等于掌握所有模组角色的特殊技能；依赖真实客户端或特殊初始化的角色仍可能不兼容，未逐个实测第三方角色模组。

## 选角失败排查

0.2.7 修正了游戏私有 `json.encode` 与标准 HTTP JSON 不兼容的问题：提示词中的单引号可能被编码为非法的 `\\'`，导致桥接返回 `invalid completion request`，模型实际没有收到请求。现在对外使用标准编码并补齐控制字符转义；桥接还将响应及模型 JSON 内容中的 Unicode 转义规范化为 UTF-8，避免中文名字或转义角色标识被游戏误读。升级后须重启世界服务器和 API 桥接；现有 API 配置不变，不增加请求次数。

日志中的 `model selected character willow` 表示模型确实选择了该角色；`character selection failed (...); fallback wilson` 表示失败回退，括号内区分接口/配置错误、超时、无效 JSON 或角色不在已启用列表。日志不输出 Key 或响应正文。模型仍可正常选择威尔逊，修复不会强制随机换角；接口不可用时仍保留安全回退。仅看到机器人采集不代表模型已接通，因为本地规划可独立运行。

0.2.9 在选角鉴权失败后，以及公屏对话遇到 `401` / 无效 Key 时，会广播明确的模型离线提示；同一 AI 的提示至少间隔 60 秒，失败消息仍保留待答。请在服务商控制台确认并重新填写可用的 **API Key**，不是网站登录密码或其他凭证，再 Apply 并重启世界。切换 Responses 不会让无效凭证生效。主动求助、出生介绍与本地生存无需模型成功，不能作为鉴权成功的证据。

## 反应速度与请求间隔

**Request interval** 是每个 AI 定时请求模型作出动作决策的间隔，单位为秒，可选 5、10、15、30、60，默认 30。五个活跃机器人在 30 秒间隔下，每分钟最多约 10 次定时请求；10 秒间隔约 30 次，5 秒间隔约 60 次。启动时每个机器人还会额外发送一次选角请求和一次初始动作请求。若上一次动作请求尚未完成，会跳过本次定时请求。默认间隔没有缩短，加快本地动作不需要增加 API 调用。

本地生存循环每 **0.25 秒**检查一次，独立于 HTTP 和模型请求，旧版为 2 秒。这减少的是调度等待，不会缩短动画、寻路或服务商响应时间。砍树、挖矿会在重新验证目标和工具后连续执行，不必每一下都请求模型。忙碌时收到的模型动作最多保留 10 秒，空闲后重新验证，生存需求优先。延迟返回的等待、闲逛指令不会打断已有缓冲动作。自主目标每秒检查一次，探索保持目的地并轮换访问区块，跟随更新最多每秒两次。尚未在实际游戏中测量帧耗时或端到端响应速度。

桥接会按字段报告无效配置：`invalid base_url`、`invalid api_key`、`invalid model` 或 `invalid messages`，不会回显提交的值。地址、Key 和模型首尾空白会被去除；Key 内部控制字符仍会被拒绝。反复出现校验错误表示请求失败，不只是响应慢，应先检查配置，再考虑缩短请求间隔。

## 模型主导的自主游戏（0.2.14）

每个 AI 由自己的模型决定目标、资源用途、探索方向和发展策略。旧版固定的“斧头 → 镐子 → 科学机器 → 背包”本地路线已退出运行调度；本地不会因为材料够了就替模型改目标，也不会在模型选择等待时自动捡东西。提示词保留开局知识供模型参考，但不强制按顺序完成。

每次请求带上模型上次选择的目标、执行反馈、库存装备、配方与科技门禁、附近资源/建筑、位置与探索记忆。模型可返回 `goal` 和 `explore`，指定附近合法坐标，或让执行器选一个较少访问的方向；支持的其他动作包括采集、吃东西、制作、放置建筑、装备、砍树、采矿、走向科学站、等待和可选跟随。执行器校验目标、工具、材料与落点；反馈“已派发”不表示实际完成，模型须根据后续观测调整。

本地每 0.25 秒处理执行与紧急保护：应对正在攻击的危险、实际黑暗和危急饥饿，并接续模型已经开始的砍挖。它不会自主补普通材料或推进科技；模型请求期间可以继续现有工作。模型接口离线时，只保留紧急保护、已有工作及幽灵复活流程，无法继续独立制订新计划。决策频率仍由 **Request interval** 决定，默认 30 秒；希望更频繁决策可手动选 5–10 秒，API 用量随之增加。本次不增加自动请求或失败重试。

支持按真实材料与原生地形校验放置科学机器、营火和石头营火；已有建筑缓冲会复用，避免落点失败重复扣料。原型制作保留角色、科技、库存和原生完成回调限制，不免费解锁配方。探索记忆有限，不是完整地图导航。

机制与配方来源见[生存研究记录](docs/survival-research.md)。模型只能组合已有动作，不能临时生成新玩法代码。烹饪、自动添燃料、复杂战斗和完整季节策略仍未实现，也不保证所有原版或模组角色长期存活。目标与库存目前不跨世界会话保存。

## 对话、求助与建议尝试

公开发言会交给一个存活 AI 回应，**不需要 @ 或指明 AI 名字**。直接在公屏说 `你好，你在做什么？` 即可；`@AI1` 或 `@自选名字` 仅用于可选的定向对话。未点名时，优先交给最近主动求助且问题仍有效的 AI，否则交给离发言者最近的 AI。一次发言不会让五个 AI 同时回答。私语、表情、未知用户及非存活真人发言不会交给模型。AI 的回复通过 `[AI 名字]` 系统聊天广播，并显示头顶气泡，不伪造网络账号。自主决策周期只执行动作，不公开播报计划；正常发言仅用于回复玩家聊天，或目标确实停滞时按冷却询问帮助。

- 模型目标的动作持续约 45 秒被执行器拒绝、且没有观测到进展时，会用中文主动询问帮助。自主模型请求不会公开说话；主动求助只由本地停滞检测触发。求助间隔至少 90 秒，问题约 180 秒后失效。
- 玩家回答是**不可信的建议**，不是必须服从的指令。模型可追问、拒绝，或把一个具体办法作为临时假设，尝试现有动作。真正尝试后，至少观察 10 秒才可能报告所缺材料有进展；75 秒仍没有进展会报告暂时无法确认。观察到进展不等于证明建议正确，更不等于永久学会了配方。普通问候不会创建试验。
- 接收建议后，该 AI 当前会话的模型动作还会经过固定限制：不允许玩家诱导攻击、点火、丢弃/赠送物品或执行代码；制作/建筑限于现有白名单，砍挖限于支持的天然树木和矿石，食物、材料、工具、科技及危险环境仍按原有执行规则验证。正常自主行为和紧急生存不会等待聊天请求完成。被限制的操作会明确拒绝，而不是宣称成功。
- 木炭是能力边界示例：可以询问原理，或尝试捡现成木炭、砍附近已经烧焦的支持树木；目前**没有受控点火动作**，玩家说“把基地烧了”不会开启新能力。聊天不能自动生成缺失的玩法代码。
- 每个 AI 只保留最近 12 条经过长度限制的对话。每位玩家对同一个 AI 的输入最多每 2 秒接收一次，聊天触发的额外模型请求至少间隔 8 秒，并与已有动作请求互斥。较新的消息不会被旧请求回复清除；短时间连续发言以最新一句为待答消息，其余保留在有限历史中。接口失败会保留待答消息供后续重试。

**用量与隐私：**聊天可能额外调用所选 AI 的模型，普通定时请求不变；聊天触发请求每 AI 最多约 7.5 次/分钟，与定时请求共享在途限制，实际可能更少。待答聊天的输出预算上限从 160 提高到 320 token，以容纳短中文回答。公开聊天内容、发言者游戏标识和有限历史会经本机桥接发送到该 AI 配置的服务商，AI 回答对所有同分片玩家可见；不要在公开聊天中发送隐私或 Key。聊天、建议与试验状态只在当前世界会话保留，不跨存档学习。已执行原生 Lua 聊天函数的模拟回归，但尚未用真实主机和远端客户端验证 C++ 消息回调与显示链路。

## Responses 接口（0.2.8）

每组配置新增 **AI N API format**：`chat_completions`（默认，兼容旧配置）或 `responses`。如果服务商使用 OpenAI Responses，必须将对应 AI 设为 **Responses**，再填写服务商规定的 API 地址、Key 与模型，例如你的 `gpt-6.1-sol`；不会自动从模型名猜测协议，也不会失败后再试另一种协议。

Responses 地址支持服务商根地址、`/v1` 或完整 `/v1/responses`：根地址补齐 `/v1/responses`，其他前缀补齐 `/responses`。选择 Responses 时不要填写 `/chat/completions`，反之亦然。桥接发送 `input`、`max_output_tokens`、`text.format`，关闭流式与存储，省略 `temperature`，从 `output` 消息中的 `output_text` 提取 JSON；拒绝、未完成或无文本会作为失败报告，不会当作成功选角。

Responses 每次输出预算上限为 **2048 token**，包含模型推理 token，以降低原来 160/320 预算截断 JSON 的风险；实际消耗由服务商返回决定，仍可能用尽预算并失败。Chat Completions 的预算与请求频率不变。Responses 不会自动解决 `HTTP 401`：鉴权、额度和服务商的协议权限仍需有效。升级后重启游戏和桥接，在配置中选择 Responses 并 **Apply** 后继续世界。本地回归覆盖原生 JSON 编码、实际 HTTP 桥接、中文名字和非威尔逊选角，尚未用你的付费接口或真实游戏窗口验证。

## API Key 存储与安全

Key 在界面中遮挡显示，但以普通游戏配置字符串保存，本模组不会加密。不要把真实 Key 放进创意工坊上传内容、Git 提交、截图、共享存档或共享配置文件。

世界服务器将每次请求及 Key 发送给本机回环桥接；桥接仅通过 Authorization 请求头将 Key 转发到你配置的 API 地址，不记录请求正文或凭据。模组未添加向客户端发送 Key 的 RPC。输入框遮挡不等于配置存储具备保密能力。

## 专用服务器配置

1. 将主模组目录复制到服务器的 `mods` 目录。
2. 在服务器的 `modoverrides.lua` 中启用模组。
3. 将 `ai_count` 设为 `0`–`5`。
4. 为每个 AI 填写 `ai_N_api_base_url`、`ai_N_api_key`、`ai_N_model` 与 `ai_N_api_format`（`chat_completions` 或 `responses`，省略时默认前者）。多个 AI 可以重复使用同一个 Key。
5. 每个地址都须兼容所选协议；不同 AI 可以使用不同的服务商和模型名称。
6. 进入世界前，在服务器本机启动 `python tools/ai_http_bridge.py`。

`modoverrides.lua` 示例：

```lua
return {
    ["ai_players"] = {
        enabled = true,
        configuration_options = {
            ai_count = 2,
            ai_1_api_base_url = "https://relay.example/v1",
            ai_1_api_key = "REPLACE_WITH_RELAY_SECRET",
            ai_1_model = "REPLACE_WITH_RELAY_MODEL_NAME",
            ai_1_api_format = "responses",
            ai_2_api_base_url = "https://api.openai.com/v1",
            ai_2_api_key = "REPLACE_WITH_OPENAI_SECRET",
            ai_2_model = "gpt-4o-mini",
            request_interval = 30,
        },
    },
}
```

配置条目的键应使用实际本地模组文件夹名。发布到创意工坊后，改为 `workshop-` 加实际创意工坊 ID。

## 生命周期与当前能力

- 地表服务器将数量限制在 0–5，并在第一个存活真人进入后启动。新世界与启用模组后继续的旧存档使用同一启动流程。
- 每个配置了 Key 的槽位会先创建 **[AI] AI N** 玩家列表条目，状态为 **Selecting**。模型独立选择名字及当前世界可用的原版或模组角色，随后在真人附近的安全地面生成，状态变为 **Alive**。重复加入事件不会重复生成机器人；缺少 Key 的槽位会跳过。
- 选角失败、返回不支持的角色或超过 60 秒时，使用支持的默认角色并记录回退信息。如果真人已断开，等待真人返回后再进入。无需额外启动真实客户端或手动点击选角界面。
- 模型可观察生命、饥饿、理智、背包数量、装备、附近可用资源及 GUID、威胁、光照、时段、配方权限与材料、建筑和当前发展目标；可请求采集、进食、制作或装备物品、使用已有工具砍树或挖矿、放置白名单建筑、探索、走向已发现的科技站、说话、等待、跟随，以及攻击非玩家目标。
- 本地四分之一秒生存循环会躲避迫近的攻击者、饥饿时吃适合且已持有的食物、收集食物和限量草枝，并在实际缺光时使用真实材料制作或装备火把。普通明亮黄昏只预留草枝，已有安全光源的夜晚不另造、不另装备火把；模型动作也遵守同一限制。已点燃的火把不会仅因自身照亮周围而被自动收起。已有移动、工作和忙碌状态会被保留。机器人没有免费物资、生命或无敌能力；模型请求失败时，本地生存行为仍会运行。
- 玩家列表支持正常滚动，显示状态与角色。机器人没有真实客户端的个人资料、静音、踢出、封禁或账号操作，不修改网络客户端表和已认证玩家数量。
- 机器人使用原生角色预制体，即使没有客户端身份，也会参与部分原生玩家玩法系统。目前仍是早期实现，不是完整玩家替代品。
- 死亡后显示为 **Ghost**。机器人会在公屏询问一次复活帮助，等待 60 秒后寻找可用的复活石或启用复活功能的复活门并尝试自行复活；复活成功后继续使用原角色和原 AI 槽位。没有可用复活点时会保持灵魂状态。机器人及背包每次世界会话都会重新创建，不作为已认证玩家会话持久保存。机器人不会迁移到洞穴，列表快照目前也仅在地表分片内复制。
- 制作支持火把、斧头、镐子和背包，允许在有效科技站旁按原生流程原型；放置支持科学机器、营火和石头营火。尚未实现完整基地经营、高级寻路、季节或 Boss 策略，以及可靠的长期自主生存。
- 桥接接受服务商根地址、`/v1` 前缀或完整 `/chat/completions` 地址。根地址补齐 `/v1/chat/completions`，其他 API 前缀补齐 `/chat/completions`。桥接添加 Authorization，游戏原生 POST 使用已知支持的四参数 `QueryServer` 调用方式。

Lua 回归覆盖进入世界、独立选角、列表复制、本地动作和请求失败。隔离离线 WeGame 环境的原生引擎冒烟测试在 Lua 初始化前被 Rail 阻止，报错 `Please make sure the TGP is running!`，结果码为 2。实际游戏画面、远端复制和长期生存尚未验证。
